# وثائق orca1store

## 1. Local Bridge

### الهدف

يربط الجسر المحلي بين Hermes والمواد التعليمية التي يتم اعتمادها داخل الجهاز. يحفظ المعرفة القابلة للتدقيق بدل نسخ نموذج مغلق أو إرسال حالة تشغيل إلى GitHub.

### دورة الدرس

`candidate` ثم طلب اعتماد محلي ثم `approved` أو `rejected`. لا توجد ترقية إلى معرفة معتمدة إلا إذا تحقق `mentor_bridge` من وجود سجل اعتماد مطابق داخل `approval_engine`.

### الملفات المحلية

- `core/mentor_bridge.py`: تخزين الدروس والمهارات والتصحيحات واللقطات.
- `core/approval_engine.py`: طلبات وقرارات الموافقة.
- `data/mentor_bridge.json`: حالة الجسر المحلية.
- `data/mentor_snapshots/`: لقطات قابلة للمراجعة.

### حدود الجسر

الجسر لا ينقل أوزان النماذج ولا يخلق اتصالًا دائمًا بـ Manus خارج جلسة العمل. النقل الفعلي يتم على مستوى النصوص، المهارات، القواعد، الاختبارات، والتصحيحات التي يسمح بها المستخدم.

## 2. Repository Layout

المصدر القابل للمشاركة يجب أن يظل منفصلًا عن حالة التشغيل. تُحفظ الأدوات والوحدات في `core/`، والمهارات العامة في `skills/`، والاختبارات القابلة لإعادة التشغيل في `data/test_*.py`، والتوثيق في `docs/`.

حالات الجلسات، طوابير الموافقة، لقطات الجسر، ملفات النتائج، وبيانات الذاكرة الخاصة لا تُعامل كمصدر. يجب أن تبقى محلية ومضافة إلى `.gitignore`.

## 3. Operational Contract

1. لا يُربط Hermes بعنوان عام.
2. لا يُرفع نموذج محلي أو مفتاح أو رمز أو ملف `.env`.
3. لا تُرسل حالة التشغيل إلى GitHub تلقائيًا.
4. أي تغيير في المصدر يمر بفحص الصياغة والاختبارات.
5. أي إجراء نشر أو قرار حساس يبقى خلف بوابة اعتماد بشرية.
6. تُحفظ المعرفة المعتمدة مع بصمة وسجل حدث ومرجع اعتماد.

## 4. Release Checklist

- تأكيد أن المستودع خاص.
- مراجعة `git status` و`git diff`.
- فحص الأسرار في الملفات الجديدة والتاريخ قبل الدفع.
- تشغيل اختبارات `data/test_*.py`.
- تشغيل Hermes محليًا والتحقق من `/api/agent/ops`.
- دفع المصدر والتوثيق فقط.
- التحقق من محتوى GitHub بعد الدفع.
